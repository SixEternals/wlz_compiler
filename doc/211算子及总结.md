Ascend 910B4 的当前可见 case 上完成 correctness 进程和 seeded `B,C,C,B` paired profile，
candidate/baseline median ratio 不超过 `1.03`。它不是官方功能通过、不是官方 speedup，也不是
Ascend A2/A3、初赛全部 case 或决赛隐藏 case 的结果。

当前 matrix 是本轮的逐算子事实入口，覆盖 21 个算子、每个 `visible_case_count=1`。所有矩阵条目
的 `correctness_status` 为 `passed`，但 `compile_status` 仍为 `unknown`；一个直接测试进程返回 0

## 真实结构性优化

### Act Quant：当前最强结构性证据

`localv-ce06de045cf9` 把原二维 grid 的“一个 program 处理最多 32 行”改为一维
`(row, quant_group)` program mapping；量化公式、scale 粒度、wrapper/JIT 签名保持不变。
当前可见 `M=8,N=256` 的 paired ratio 为 `0.0258000504`；隔离 probe `M=64,N=512`、round-scale
路径 ratio 为 `0.1567312644`，两者 correctness 均通过。额外 correctness probe 覆盖
`M=1/8/16/64`、`N=128/256/512`。

首次实验中曾使用数学等价的 `amax / 448` 表达式；因边界舍入风险，已回退为 baseline 的
`amax * (1 / 448)`，随后重新跑 correctness/performance。旧候选 `localv-d441fb23be18`
只增加 `num_warps=4`、ratio `0.9992566758`，不能作为真实优化；当前 matrix 已改用 `ce06...`。
这些结果仍是 910B4 开发证据，且大 `M`、更大 `N`、其他 block size 和 A2/A3 尚未验证。

### Chunk Cumsum：结构性 block/index rewrite

`localv-8a4053789ffa` 改变 `BLOCK_SIZE_H`、pid/index 类型和 mask/指针表达式，不是单一 launch
开关。当前 ratio `0.1568577236`；visible case 对 `dA_cumsum` 与 `dt_out` 均有 PyTorch
`assert_close`。尚无独立 shape paired probe，需优先补 seqlen/chunk/head 除尽与非除尽边界。

### EP Gather：结构性 token/D-block mapping

`localv-548c43fedfae` 将二维 program grid 改为 token block program，并在 program 内遍历 hidden
dimension blocks；ratio `0.4806480915`，当前测试有 reference `allclose`。需补 token tail、top-k、
expert map/负 expert id、hidden-size 分块边界；当前大收益不能外推。

### Correct Attn：窄的 index-width 结构变化

`localv-c5d774ed9122` 将两个 `program_id` 从 int64 改为 int32，ratio `0.9319041353`；当前
output 与 VLSE 都有 allclose reference。它不是完整算法重写，需补大索引、不同 B/H/D/N 与 NaN/Inf
组合后再判断是否值得写入经验。

Chunk State `num_warps=2`、count `BLOCK_SIZE=512`、dequant `num_warps=1`、log-softmax

4 个 neutral-only 候选分别是 copy-page 的 comment-only、per-group 的 format-only、quantize-k-cache
的 comment-only、set-k-and-s 的 identifier/type-comment variant。它们只能证明当前 case 不退化，
不应进入“真实优化策略”统计或 Experience 成功样本。

## Correctness 与性能证据边界

- 当前 matrix 每个算子只有一个 visible case；每个角色为同设备、同频率、seeded `B,C,C,B` 两次
  profile。`ratio<=1.03` 是本机 qualification 阈值，不是官方 speedup。
- correctness artifact 记录 baseline/candidate 直接测试进程通过；它通常绑定 source/test/manifest
  hash，但没有独立 compile 阶段字段，因此 matrix 保持 `compile_status=unknown`。
- Chunk State `localv-243d...` 和 Selective `localv-5bb...` 各有一个隔离 shape：ratio 分别为
  `1.0026768`、`0.9767981`；它们不是官方 case 2。
- Act Quant 有 `M=1/8/16/64,N=128/256/512` correctness probe 及 `M=64,N=512` paired probe；
  仍不能代表完整 case matrix。
- 其他算子的可见测试可能在一个脚本中包含多个断言，但当前 qualification sidecar 仍只提供一个
  case-id，不能把一个总 ratio 拆成逐 shape 结论。
- 910B4 不等于官方 A2/A3；官方 A2/A3、初赛其余 case、决赛隐藏 case、官方 functional pass、
  官方 latency/speedup/ranking 均为 unknown。

## 已拒绝与回退候选

失败候选必须保留为带 source/test/environment 的反例，不能删除或只写自然语言结论：

- Act Quant 初始 `amax / 448` 表达式已回退；最终候选恢复 baseline 表达式后才作为 `ce06...` 计入。
- Pack Seq prefix-sum `ebfbd9806f27` 虽在额外 `B=1,D=7`、含零长度/三维 `B=5,D=15` correctness
  通过，但 paired ratio `1.0873364743` 超过 1.03，拒绝替换 `53c52b9429ff`；wrapper 新增的
  `torch.cumsum` 也未被目标 kernel profile 计时，不能据此晋升。
- Dequant probes 的约 `1.096`、`1.042`、`1.064`、`1.043` ratio 均回归，最后保留 `num_warps=1`。
- Count `BLOCK_SIZE` cap 2048 ratio `1.0788`；TRTLLM `num_warps=4` ratio `1.0357`；per-group
  `BLOCK_SIZE_K=8->16` ratio `1.4681`，均拒绝。
- Per-token 一次 correctness/benchmark 重叠的 sidecar 标为 `invalid-overlap`，不计入 matrix；
  修复后独立重跑才计入。
- Chunk State 旧 profile 因 `_mix_aic` 名称解析缺口被保留为 `failed-parser-exact-name`，修复
  parser 后才得到当前两 shape 证据。
