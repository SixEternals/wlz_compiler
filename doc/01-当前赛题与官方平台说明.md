# 01 当前赛题与官方平台说明

更新日期：2026-07-11  
用途：作为 `doc/` 系列的第一篇，快速确认当前选题、官方平台和资料入口。

## 1. 一句话结论

本项目选择的是第八题：

> **2026 年全国大学生计算机系统能力大赛编译系统设计赛（华为毕昇杯）
> 编译系统挑战赛——“基于进化算法的 Triton 自动优化系统”。**

项目目标不是重写 Triton-Ascend 或 AscendNPU IR，而是在官方给定的 agent
框架中，设计进化搜索、候选生成、失败复用和预算控制方法，自动优化 Triton 算子。

## 2. 八个候选赛题中我们选的是哪一个

| 序号 | 赛题 | 本项目是否选择 |
| --- | --- | --- |
| 1 | 基于 AscendNPU IR 的 NPU 自动融合代码生成与调优 | 否 |
| 2 | 基于 Triton-Ascend 构建昇腾亲和算子 | 否 |
| 3 | 动态算子图编译与并行调度 | 否 |
| 4 | 仓颉高性能 Range Analysis 分析 | 否 |
| 5 | 仓颉数据竞争静态检测 | 否 |
| 6 | 仓颉代码片段语义检查 | 否 |
| 7 | Java 虚拟线程实现机制优化 | 否 |
| **8** | **基于进化算法的 Triton 自动优化系统** | **是，当前主赛题** |

Triton-Ascend 和 AscendNPU IR 可能是第八题中用到的基础设施或可选观测来源，
但它们各自也对应独立赛题。不能宣称我们同时选了第一、第二和第八题。

## 3. 第八题的官方硬约束

根据 2026 年 4 月中文技术方案：

- 在大赛给定的 agent 框架中设计进化算法。
- 必须使用提供的环境和接口，不可改变接口调用方式。
- 输入是大赛提供的待优化 Triton 代码库，不允许参赛队手工修改候选代码。
- 每个算子最多运行 20 分钟或消耗 20 万 token，任一上限先到即停止。
- multi-agent 方案会累加所有 agent 的 token 消耗。
- 统一接口最多返回 5 个候选版本。
- 至少一个非原样候选需成功编译并通过全部测试。
- 初赛客观分为 Passing Rate 30% + 性能 70%。
- 真实性能由鲲鹏 920 + Ascend A2/A3 + openEuler 平台测量。

### 4.1 GitLab 里有什么

官方公开资料仓库：

<https://gitlab.eduxiji.net/csc1/nscscc/compiler2026>

当前公开树中主要是：

- 2026 大赛章程和各赛题技术方案 PDF；
- SysY 文档；
- ARM/RISC-V 实现赛相关测试 zip；
- GitLab 默认 README。

截至 2026-07-11，该公开仓库**没有**第八题的官方 agent/executor 源码。
参赛队需自行创建 GitLab 项目，并把 HTTPS 项目链接提交给评测系统。

### 4.2 GitCode 里有什么

GitCode 中的 `Ascend/triton-ascend` 是第八题使用的底层编译基础设施，包括源码、
安装说明和 Triton-Ascend 相关文档。它不包含我们的参赛项目，也不是提交评测的地方。

### 4.3 HiDevLab 里有什么

官方技术方案说明，参赛队可申请权限创建 Ascend IDE 开发环境，用于真实昇腾
硬件上的开发和调试。申请时需注明“华为毕昇杯挑战赛”、队伍名和赛题名。
未实际获得环境前，不假设其目录、凭据、CANN 版本或是否预置 agent 框架。

## 5. 从开发到评测的实际链路

```text
compiler.xtnl.org.cn
  报名、查看技术方案与官方通知
        |
        v
course.educg.net
  进入具体赛题，管理 GitLab 账号，提交评测请求
        |
        v
gitlab.eduxiji.net
  自行创建参赛仓库，提交 agent 工程并保留指定版本
        |
        v
竞赛评测系统
  根据申请从 GitLab 拉取指定版本
        |
        v
鲲鹏 920 + Ascend A2/A3 + openEuler
  自动执行编译、功能测试和性能测试
```

官方作品提交说明的关键原文是：

> 要求在 GitLab 项目内开发，并通过 GitLab 项目链接提交评测。
> **注意仅支持 HTTPS，不支持 SSH。**

因此，GitLab 负责托管代码，竞赛评测系统负责测试。不应将两者合并成“GitLab
自己完成所有评测”。

## 7. 官方 agent 框架的当前状态

官方 PDF 明确承诺提供基础 agent 代码框架、安装环境和相关文献，但没有在 PDF
中给出框架的具体下载地址。官方公开 GitLab 资料仓也暂无该源码。

当前能确认的正规获取途径只有：

1. 用已报名队伍账号进入 `course.educg.net` 的具体赛题页，查看内部附件和环境说明。
2. 在官方参赛队 QQ 群 `700621252` 询问框架下载位置和当前版本。
3. 获得 HiDevLab 环境后，按官方环境说明检查是否预置框架。

不把公开参赛队仓库或文件中“组委会提供”的作者声明当成官方 provenance。
