# doc/learn 学习目录

这个目录用于保存“边验收边学习”的导读文档。

导读文档不是泛泛的笔记，而是面向人工验收的小单元材料。每篇导读都应该帮助读者在 5-15 分钟内理解一个具体对象，并知道如何验收它。

## 编号规则

文件名必须使用：

```text
NN-主题导读.md
```

其中：

- `NN` 是两位递增编号，例如 `01`、`02`、`03`。
- `主题` 要具体，能看出导读对象。
- 文件名必须以 `导读.md` 结尾。

示例：

```text
04-LocalExecutor导读.md
05-cache-jsonl导读.md
06-per-group-transpose算子导读.md
```

不要新增重复编号。

如果目录已有导读，使用当前最大编号的下一个编号；不要重排已有编号。

## 写作规则

所有新导读都必须遵守：

```text
doc/learn/导读写作规范.md
```

AI agent 新增或修改本目录导读前，必须先阅读该规范。

## 验收建议

新增一篇导读后，至少检查：

```bash
find doc/learn -maxdepth 1 -type f -print | sort
sed -n '1,80p' doc/learn/新文档.md
```

人工重点看：

- 编号是否重复。
- 标题是否具体。
- 是否说明“这个文档解决什么问题”。
- 是否有可运行命令或明确人工验收入口。
- 是否清楚区分 mock/proxy 与真实 Ascend 性能。
- 路径和命令是否在当前工作树真实存在。
- 项目状态是否链接 `doc/README.md`，而不是复制一份容易漂移的快照。
